# Розгортання «Незбіг» на Vercel

## Збірка

У проєкті використовується статичний Vite-клієнт і Express через `api/[...path].js`.

- Install command: `npm ci`.
- Build command: `npm run build`.
- Output directory: `dist`.
- Серверна компіляція: `.vercel-server`; entrypoint API імпортує з неї Express.
- `vercel.json` містить rewrite для API, SPA-маршрутів та `maxDuration: 300` для функції.

Фактичний доступний час виконання залежить від налаштувань і плану Vercel. Для Vite 7 потрібен сумісний Node.js; конкретну версію задайте в налаштуваннях проєкту й перевіряйте за lockfile.

## Змінні середовища

| Змінна | Призначення |
| --- | --- |
| `JWT_SECRET` | Випадковий стабільний секрет від 32 символів; потрібен у production |
| `CLIENT_URL` | Публічний HTTPS origin, наприклад `https://nezbig.vercel.app` |
| `AUTH_ALLOWED_ORIGINS` | Додаткові точні HTTPS origins через кому; без wildcard |
| `REDIS_URL` | Постійне сховище користувачів і звітів, потрібне для надійної роботи на serverless |
| `KV_REST_API_URL`, `KV_REST_API_TOKEN` | Необов'язковий KV REST для розподілених пошукових/page/job кешів і альтернативного зберігання звітів |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | Вхід через Google; Client ID також використовується клієнтським Drive-підключенням |
| `GOOGLE_REDIRECT_URI` | Точний callback, наприклад `https://nezbig.vercel.app/api/auth/google/callback` |
| `SERPER_API_KEY`, `TAVILY_API_KEY`, `BRAVE_SEARCH_API_KEY` | Необов'язкові пошукові сервіси |
| `GOOGLE_SEARCH_API_KEY`, `GOOGLE_SEARCH_ENGINE_ID` | Окремий Google Custom Search; не пов'язаний із квотою входу Google |
| `NVIDIA_NIM_API_KEY`, `NVIDIA_NIM_MODEL`, `NVIDIA_NIM_FALLBACK_MODELS` | Додаткова ШІ-думка через NIM; fallback-моделі через кому |
| `OPENROUTER_API_KEY`, `OPENROUTER_MODEL`, `OPENROUTER_FALLBACK_MODELS` | Резервна ШІ-думка через OpenRouter |
| `COHERE_API_KEY` | Необов'язкове reranking кандидатів |
| `SEARXNG_URL` | Необов'язковий резервний пошук DuckDuckGo через SearXNG |

Змінні не слід вважати налаштованими лише тому, що їхня назва є в таблиці. Порожній або невалідний ключ не надає доступу. `OPENALEX_API_KEY` нинішнім адаптером не використовується.

Налаштуйте потрібні змінні для кожного середовища Production/Preview окремо. Для Preview використовуйте власні точні origins і callback відповідного середовища. Після зміни змінних виконайте нове розгортання. Секрети не передавайте в чат і не записуйте в README.

Випадковий секрет можна згенерувати локальним криптографічним генератором; вигадувати фразу вручну не потрібно. Зміна існуючого JWT-секрету завершує чинні сесії.

## Постійне сховище

На Vercel локальні файли й пам'ять процесу не є спільним сталим сховищем. Для користувачів використовується Redis або локальні файли; KV REST сам по собі не покриває всі шляхи користувацьких даних. Тому для облікових записів на Vercel потрібен `REDIS_URL`.

`REDIS_URL` підтримує звіти/користувачів, але пошуковий `DistributedCache` використовує KV REST. Без KV REST ці кеші працюють у пам'яті окремого інстанса. При недоступному налаштованому remote-сховищі читання звітів не повинно підмінятися застарілою локальною копією.

У режимі Vercel базовий scan виконується синхронно всередині запиту: фонове завдання після відповіді не вважається надійним. Довгі документи можуть перевищити час функції або квоти провайдерів.

## Розмір файлів

Ліміт Multer у застосунку — 50 MiB. Однак Vercel Functions має нижчий ліміт payload: на момент перевірки документація вказує 4,5 MB для request/response. Multipart містить додаткові дані, тому файл має бути меншим за повний ліміт запиту. Завантаження великих файлів потребуватиме окремого прямого upload у сховище; цей потік зараз не реалізований. Див. [офіційні обмеження Vercel](https://vercel.com/docs/functions/limitations).

## Перевірка після розгортання

1. Дочекайтеся статусу Ready саме для потрібного Git-коміту.
2. Відкрийте головну сторінку та `/api/health`; health перевіряє API, але не готовність Redis чи зовнішніх ключів.
3. Виконайте невелику перевірку тексту. Перегляньте фактичний стан провайдерів, а не лише відсотки.
4. Перевірте вхід, історію та відкриття приватного звіту після нового сеансу/інстанса.
5. Перевірте окремо помилку та успіх ШІ-думки, експорт, видалення звіту.

Цей документ не стверджує, що всі ці production-сценарії вже пройдено в останньому перегляді.

## Якщо Google не працює

Вхід Google, Drive і Google Custom Search — різні API та дозволи. Працездатний вхід не підтверджує доступ до пошуку. Раніше UI позначав будь-яку невдалу відповідь як «ліміт квоти»; це виправлено. Перевіряйте теперішній код причини, налаштування API/ключа та доступність сервісу в Google Cloud. Реальний стан квоти облікового запису застосунок без відповіді провайдера не встановлює.
